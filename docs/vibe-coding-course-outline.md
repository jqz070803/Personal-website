## 1. 课程主线

把个人主页做成一个**可发布、可反馈、可持续改进的真实产品**。

从能看的本地版本出发 → 多轮打磨 → 公开发布 → 收集真实反馈 → 完成第一月版本，并把同一套方法迁移到自己的小项目。

## 2. 总分结构（合计 20%）

| 课程范围 | 核心项目 | 占比 |
| --- | --- | --- |
| 阶段一至阶段四 | 个人主页（V1 → V4） | 10% |
| 期末扩展 | Digital Twin、个人知识库及主要新功能 | 5% |
| 独立小作业 | 另一个非个人主页的网站或小程序 | 5% |

每个课堂知识讲解不超过 60 分钟，其余时间用于独立制作、测试和向老师寻求指导。

## 3. 四个阶段

| 阶段 | 版本 | 你要完成的变化 | 为什么 |
| --- | --- | --- | --- |
| 阶段一 | V1 | 先做出能看的个人主页并能本地预览 | 把想法变成可观察的产品 |
| 阶段二 | V2 | 根据自己的判断进行多轮、小步打磨 | 学习把模糊审美变成可执行修改 |
| 阶段三 | V3 | 加入 Feedback，并公开发布到 GitHub | 让真实访问者可以使用和回应 |
| 阶段四 | **V4** | **根据真实反馈做出有依据的改进** | 体验"听取用户—做决定—再测试" |
| 期末扩展 | — | Digital Twin、个人知识库、项目库和主要新功能 | 把主页从展示页继续发展成个人产品 |
| 独立项目 | — | 制作一个非个人主页的网站或小程序 | 把方法迁移到新的问题和场景 |

> 完成标准：每个阶段都有最低任务。完成最低任务即可满足课程要求；**增加功能、使用更复杂的模型或选择不同工具，不会自动获得额外分数**。

### 阶段一｜先做出一个能看的版本（V1）
- 最低成果：可预览（本地能打开）、内容真实（可核验、不虚构）、结构清楚（你是谁/做过什么/下一步）、第一版记录（保存 V1 并记录下轮重点）。

### 阶段二｜用多轮打磨形成自己的版本（V2）
- 最低成果：多轮迭代（不止改一次颜色或文字）、版本记录（保存 V1 与 V2，能用一两句话说明每轮变化）、代表性证据（前后版本截图或链接）、可用性（V2 仍能正常打开，核心信息与导航未被改坏）。

### 阶段三｜加入 Feedback 并公开发布（V3）
- 最低成果：公开链接（V3 可公开访问）、可提交反馈（无需登录，提交后有清晰提示）、可查看反馈（Supabase Dashboard 中能看到）、安全与隐私（前端不暴露 secret key，不收集敏感个人信息）。
- 课后任务：邀请**至少 3 位不同的人**（亲人、同学、已工作的朋友或 HR 等）访问公开网站，收集 **3–5 条具有不同意义的反馈**（内容、结构、使用体验或新需求）。

### 阶段四｜用真实反馈完成第一月版本（V4）
- 目的：把反馈转化为产品决定，而不是简单"照单全改"。判断哪些问题值得优先处理，完成 V4，并验证修改没有破坏原有功能。
- 你会学到什么：
  - 区分**事实问题、个人偏好和新需求**；
  - 对每条反馈做决定：**采纳 / 部分采纳 / 暂缓 / 不采纳，并说明理由**；
  - 在公开版本上重新测试核心路径，确认反馈功能和页面仍然可用；
  - 用简短复盘说明：用户说了什么、你改了什么、下一步还可以做什么。

## 4. 第一月提交（主页部分，共 10%）

| 提交内容 | 要求 |
| --- | --- |
| V4 公开链接 | 能访问的最终第一月版本 |
| 版本链 | V1 → V2 → V3 → V4 的主要节点和变化说明 |
| 反馈证据 | 至少 3 位**不同类型**反馈者、3–5 条有意义反馈；可提供代表性截图或记录 |
| 改进说明 | 反馈如何影响你的决定，以及修改后的验证结果 |

## 5. 期末扩展与独立项目

### 主页扩展（5%）
在第一月版本基础上继续完成一个**有实质意义的扩展**，方向包括：
- **Digital Twin**：建立与自己相关的知识库，并连接到个人主页，使回答更贴近真实的你；
- 本学期开始、进行或完成的项目；
- 一个主要的新功能或产品能力。
> 仅修改颜色、字体或少量文字，不算主要扩展。

### 独立小作业（5%）
使用同样的 Vibe Coding 方法，制作一个**不是个人主页**的网站或小程序，提交可访问版本及简短迭代说明。

## 6. 评分与提交要求

| 评分项 | 占比 | 核心判断 |
| --- | --- | --- |
| 个人主页：阶段一至阶段四 V4 | 10% | 完成最低任务；有版本链、代表性证据和反馈驱动的改进 |
| 个人主页：期末扩展 | 5% | Digital Twin / 知识库连接和（或）一个主要新功能 |
| 独立小作业 | 5% | 完成一个非个人主页的网站或小程序，并迁移迭代方法 |
| 合计 | 20% | — |

- 评分原则：看最低任务是否完成、过程是否可解释、最终版本是否可用。**不会因功能数量、模型复杂度或工具品牌自动加分**。
- 过程证据：**不需要提交完整聊天记录**。保留代表性证据即可，如关键迭代对话片段、前后版本截图、Git checkpoint 或版本说明、反馈记录。
- AI 使用与学术诚信：
  - 可以使用自己选择的 AI 模型、代码工具和辅助服务；
  - 必须理解并检查最终内容：个人信息真实、代码要测试、版本变化要能解释；
  - 不得抄袭他人作品、违反开源许可、**伪造反馈或截图**、冒用他人身份，或把密钥和隐私数据发布到公开仓库；
  - AI 生成内容不准确或不适合公开，由你负责修改、删除或说明。

## 7. 记住四句话

先做出来，再逐步改；一次改一类问题；发布后认真听取反馈；每次提交都能解释自己的决定。
